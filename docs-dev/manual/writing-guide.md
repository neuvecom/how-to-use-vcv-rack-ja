# 記事の書き方ガイド

「ゼロからの VCV Rack」の記事を書くときのルールです。読者は **DTM や音楽制作がまったく初めての人** を想定します。

## 1. 基本方針

- **1 記事 1 テーマ**。1 本で 10〜15 分で読み終わり、手を動かして終われる分量にする
- **結論・ゴールを先に書く**。「この記事でできるようになること」を冒頭に置く
- **専門用語は初出で必ず説明する**。説明できない用語は使わない
- **手順は番号付きリスト**にし、1 ステップ 1 操作にする
- 読者が **実際に音を出して確かめられる** 構成にする（できる記事では最後に「試してみよう」を置く）

## 2. 記事の構成（テンプレート）

テンプレートは [article-template.md](./article-template.md) をコピーして使います。

| 見出し | 内容 | 必須 |
|---|---|---|
| （冒頭） | この記事でできるようになること、所要時間、前提となる記事 | ○ |
| 手順・本文 | 番号付きの手順、または解説 | ○ |
| うまくいかないときは | よくあるつまずきと対処 | できるだけ |
| 試してみよう | 自分で手を動かす小さな課題 | 音を出す記事では ○ |
| まとめ | 3 行程度の振り返りと、次に読む記事 | ○ |
| 確認した環境 | VCV Rack とプラグインのバージョン | ○ |

## 3. 表記ルール

| 項目 | ルール | 例 |
|---|---|---|
| 文体 | です・ます調 | 「ケーブルをつなぎます」 |
| ソフト名 | 正式名称。初出は「VCV Rack」、以降も略さない | ✕ Rack、ラック |
| モジュール名 | 英語表記のまま、初出で役割を添える | 「VCO（音を作るモジュール）」 |
| メニュー・ボタン名 | 画面の表示どおり英語で、かぎかっこで囲む。階層は「 > 」でつなぐ | 「File > Save」 |
| キー操作 | `Ctrl`+`S`（Windows / Linux）、`Cmd`+`S`（Mac）のように両方書く | |
| 数字 | 半角 | 2.6.6、44100 Hz |
| 英数字と日本語の間 | 半角スペースを入れる | 「VCV Rack を起動」 |
| カタカナ語 | 長音を付ける | インターフェース、パラメーター、フォルダー |

### 用語の言い換え（初出での説明例）

| 用語 | 初出での説明 |
|---|---|
| モジュール | 1 つの機能を持った部品。VCV Rack ではこれを並べて音を作る |
| パッチ | モジュールとケーブルのつなぎ方の組み合わせ。保存すると `.vcv` ファイルになる |
| ケーブル（パッチケーブル） | モジュール同士の信号をつなぐ線 |
| CV | 「Control Voltage」の略。つまみを自動で動かすための信号 |
| ゲート | 「鍵盤が押されている間」を伝える信号 |

用語集（`src/content/docs/glossary.md`）にも同じ説明を載せ、表現をそろえます。

## 4. 画像・音・パッチファイル

- 置き場所
  - 画像: `public/images/<記事のパス>/` 例: `public/images/basics/install/01-download.png`
  - 音: `public/audio/<記事のパス>/`（mp3、30 秒以内を目安）
  - パッチ: `public/patches/<記事のパス>/`（`.vcv`）
- 画像はスクリーンショットに番号を付け、本文の手順番号と合わせる
- 画像の代替テキスト（alt）には「何が写っているか」を書く
- **画像がまだない箇所** には次のコメントを入れ、あとで差し替える（サイトには表示されません）

  ```md
  <!-- 画像: Module Browser を開いたところ。左に検索欄、右にモジュール一覧 -->
  ```

## 5. Starlight の便利な書き方

```md
:::note
補足情報
:::

:::tip[ポイント]
知っておくと便利なこと
:::

:::caution
注意すること（データが消える、音が大きいなど）
:::
```

- 音量に関わる操作では、必ず `:::caution` で「最初は音量を下げてから」を書く

## 6. 進捗管理との関係

- `src/content/docs/basics/` と `src/content/docs/workshop-lunar/` 配下の記事は、自動で「レッスン」になり末尾に「完了」ボタンが付きます
- 並び順は frontmatter の `sidebar.order` で決まります。マイページの並びも同じです
- 記事のファイル名（URL）を変えると、それまでの完了記録が引き継がれません。公開後はファイル名を変えないでください

## 7. 確認した環境の書き方

記事の最後に、内容を確認したバージョンを書きます。

```md
## 確認した環境

- VCV Rack 2 Free 2.6.6（macOS 15 / Windows 11）
```
